## Brazilian fiscal/legal terms — LEGAL_DOMAIN_INTENTIONAL (closed by documentation, not translation)

Per `20260918000045_RenameValorFieldsOnInvoices.ts`'s own header (the policy was already decided and executed for the `valor`-prefixed subset; this registers it formally for the rest of the cluster): these are official Brazilian tax/legal terms with no precise English equivalent. Translating the **identifier** (not just the label) would reduce precision for anyone auditing tax compliance. Display labels are already PT-BR via `field-labels.pt-br.ts`, independent of this decision.

**KEEP_LEGAL_PT_IDENTIFIER, no code change**: `cpf`/`cpf_encrypted`, `cnpj`/`cnpj_encrypted`, `cpf_cnpj`/`cpf_cnpj_encrypted` (polymorphic PF/PJ tax ID — the PF/PJ distinction is real and drives validation), `cfop`, `iss`/`issqn`/`aliquota_iss`/`iss_retido`, `pis`, `cofins`, `inss`, `ir`/`ir_amount` (register an explicit `IRRF` alias in this map, not a rename), `csll`, `base_calculo`, `aliquota`, `natureza_operacao`, `codigo_servico_municipal`, `codigo_municipio`, `inscricao_estadual`/`inscricao_municipal`, `regime_tributario`/`simples_nacional`/`lucro_presumido`/`lucro_real`, `nfse`/`nfe`/`nfce`/`tipo_nota`, `serie`, `tomador` (root term — the legal service-recipient/payer-of-record role in an NFS-e, distinct from a generic "customer"), `prestador` (service-provider role), `tomador_uf` (UF is an official Brazilian state-code designator), `tomador_cep` (CEP is an official postal-code designator), `numero_nota_fiscal` root (`nota_fiscal`).

**NORMALIZE_TECHNICAL_EN_WITH_PT_DISPLAY (generic tokens incorrectly caught in this cluster, not yet executed)**: `tomador_endereco`→`tomador_address`, `tomador_cidade`→`tomador_city`, `tomador_email` (already EN). `numero_nota_fiscal`'s `numero_` prefix → `nota_fiscal_number` (low priority).
