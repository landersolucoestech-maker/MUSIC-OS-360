# Technical language normalization: before and after (comparative report)

Scope: technical names (identifiers, persisted names and values, API fields, routes, tooling messages, data files, documentation language) and the environment-variable contract. Not in scope: the destructive column drops, the PII scrub, the product decisions and the external CI confirmation, which stay protected and are listed at the end.

## Method

- Baseline `02f1ee8a75be16a93f91caae1d8a78702ab2f4fc` (2026-09-26), the parent of `d902ace6`, the first commit that created the canonical map and the census tooling (full history fetched; the clone was shallow before).
- The CURRENT detectors (same lexicon, same scanners, same surfaces) run over the baseline tree with an empty exception index and over the audited tree with the real ledger. The only variable is the repository.
- Generated artifacts: `docs/naming/audit/normalization-audit-summary.md|json`, `docs/naming/audit/normalization-audit-matrix.tsv` (every item of either state, not a sample) and `docs/naming/audit/normalization-audit-report.md` (findings and decisions); the environment matrix is `docs/engineering/env-contract-matrix.md|tsv`.
- Independent checks that do not use the census scanners: a separate AST pass over the ledger's legacy aliases (0 uncovered), a live-schema cross-check (entity columns against the migrated catalog, legacy aliases against live columns, concept names against the live schema), a dead-code proof for removed artifacts, the provider-residue guard, gate-level mutation tests (a clean tree passes, nine injected defects each fail the real gate, a ledger row covers exactly its file and name), and the environment contract gate with its own mutation tests.

## What the comparative audit corrected (this and the previous order)

1. Residue census generated invalid SQL (exit 2) and was outside CI: fixed, tested, added to CI and to `naming:check`.
2. `lead_interactions.data` (a date column named with the Portuguese word) renamed to `occurred_at` across database, entity and web, with a guarded reversible migration.
3. `payment_events.status` was written by raw SQL but not mapped by the entity: mapped.
4. Operator SQL scripts inserted into columns that no longer exist: corrected and executed against the migrated schema.
5. Two new gate surfaces close real coverage gaps (data files; tooling messages) and a third closes the largest one found by the independent pass: member reads of legacy fields (`row.titulo`, `row['nome']`), which the declaration-based scan could not see. It exposed stale reads left behind by the rename work, now fixed: the work and phonogram forms parsed a JSON copy of the project tracks that the API no longer sends (the auto-fill of composers and producers silently never worked); the invoice provider card read removed company-profile names (and a street number taken from an unrelated invoice field), so the company address and bank lines were always empty; the user detail dialog showed the removed `setor` name; the employees filter sent the deprecated `setor` parameter; the release track list ignored the canonical `artist` key; five fallbacks to removed Portuguese fields were dropped; the conversation view model's `assunto` became `formSubject` (the external website-form key is kept as a documented boundary).
6. 91 ledger rows were added for member reads that are legitimate: the legacy-name mapper modules and role-slug constants (temporary compatibility, each with a covering test), compatibility tests, an external provider contract (ViaCEP), the legal-domain acronym LGPD and spreadsheet input headers.
7. Ledger corrections: four concepts that were still "open" although migrated were closed; four undeclared product decisions are now explicit blockers.
8. Dead artifacts removed after a zero-consumer proof (owner authorization 2026-10-03): `apps/api/migrate.mjs`, `apps/api/seed.mjs`, `apps/api/drizzle/` (and the ledger rows, the preflight allowlist entry and the stale comment that existed only for them).
9. Protected templates: 61 comment lines translated in four `.env*` files under the owner's authorization (the 48 identified plus 13 more found with a lower detection threshold: section headings and one stale reference to a removed script verdict string); a before and after comparison proves only comment lines changed (same line count in every file, every non-comment line byte-identical; no name, value or placeholder touched).
10. Documentation: stale statements corrected (`MOCK_MODE`, development setup, `VITE_API_URL`).
