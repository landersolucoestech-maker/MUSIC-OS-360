# Re-audit fixes — v1.2.1

The v1.0 and v1.1.0 archives are superseded and should not be used. v1.2.1 was rebuilt after a line-by-line and cross-file re-audit.

## Material corrections since v1.1.0

- Replaced stale/unsupported agent frontmatter assumptions with validation against the current Claude Code subagent contract.
- Agent Teams are no longer globally enabled; T3 teams are explicit opt-in only.
- `TaskCompleted` now follows the official contract: `task_id`/`task_subject` input and exit code 2 for dependency rejection.
- Removed the parallel LLM Stop verifier. Stop now has one deterministic command gate; semantic reviews occur before Stop according to T2/T3 policy.
- Corrected the Stop gate to consume live `background_tasks` and to acknowledge Claude Code's finite Stop-continuation protection rather than claiming an absolute gate.
- `PostCompact` is side-effect/logging only. Recovery context is injected on `SessionStart` with compact source, backed by `PreCompact` checkpoints.
- File baselines are captured from the exact bytes immediately before Edit/Write/NotebookEdit. A file being clean at session start no longer produces a missing pre-change hash.
- SHA-256 is computed over raw file bytes, not a JSON representation of a Buffer.
- Symlink/path resolution is constrained to the repository; writes to internal symlinks require explicit approval and out-of-project/ops writes are rejected.
- Shell mutation tracking now reconciles pre-command dirty snapshots, post-command Git state, commit-to-commit deltas, and untracked deletion.
- Mission rollover resets task-scoped state so a new request cannot inherit prior PASS evidence, blockers, touched files, or failure fingerprints.
- Touched-file ledger hashes/existence are rechecked against the live filesystem at completion time.
- Added memory supersede/invalidate lifecycle and an improvement-close lifecycle instead of append-only stale authority.
- Removed dependencies on the legacy agent-documentation directory and redundant inherited references.
- Fixed the status line schema mismatch (`tasks` is an object keyed by ID, not an array).
- Removed path-scoped permission rules for tools whose permission matcher does not provide the claimed protection.
- Database/RLS commands are not standing-allowed merely because their names say `verify` or `check`; they require current source/side-effect classification and approval when relevant.
- Real `.env` files are denied through direct Read/Edit permissions and shell access is classified; templates remain readable.
- Hook commands use exec-form `command + args` where project-path arguments are required, reducing quoting differences between shells.
- Routed launcher strips pre-existing ownership headers, clears direct Anthropic environment credentials before Claude starts, and applies the gateway credential only when configured.
- Headroom changed from blind reuse of port 8787 to pack-owned PID/port/target metadata on configurable default port 18787.
- Corrected documentation counts to **16 agents, 13 rules, 18 Skills**.
- Added explicit current-upstream OmniRoute/Claude Code provider-dispatch risk; safe default route is now native, with stack/router modes explicit.
- Pack semantic validator now recursively checks agent/Skill uniqueness, supported fields, hook topology, permission hazards, local Markdown links, required files, and exact project counts.
- Operational-state parse failure now fails closed instead of silently creating a fresh empty state that could erase task truth.
- Every distinct mission now receives its own mission-start baseline, including missions created through `ops.mjs mission --new`; later SessionStart baselines cannot absorb unrelated mid-mission changes.
- Completion reconciliation now includes committed deltas between mission baseline HEAD and live HEAD, not only working-tree/untracked changes.
- Task dependency removals now reconcile reverse edges as well as forward edges.
- `waiting` is an explicit non-completion state that is accepted only with a live Stop-event background task or session cron and resumes to the same mission.
- Subagent stop fallback IDs now derive from the same transcript-path hash used at start when `agent_id` is unavailable.
- Doctor Node validation now enforces the exact OmniRoute 22.x floor including patch version (`22.22.2`).

## Non-claim

v1.2.1 is a corrected and audited **pack**. It is not represented as end-to-end production-validated against the real Music OS 360 checkout, database, credentials, provider accounts, or an installed Claude Code runtime until the environment checks in `VALIDATION-REPORT.md` and `INSTALL-CHECKLIST.md` are executed there.
