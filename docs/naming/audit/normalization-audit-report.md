## Findings corrected in this audit

1. Residue census derived invalid SQL for the jsonb array guard (`ARRAY[...]]`), so the census ended with exit 2 and never reached its last checks; it was not in CI and its derivation test only matched the prefix. Fixed, balanced-bracket assertion for every derived check, unit test, CI step added, and its tests are now part of `pnpm naming:check`.
2. `lead_interactions.data` (a timestamp named with the Portuguese word for date; the lexicon cannot flag `data`) was a NOT_NORMALIZED column across all layers. Renamed to `occurred_at`: guarded reversible migration `20261003000001` (up, down, up and a second up verified on the disposable database), entity, web reader (`occurredAt`, with a read-only fallback to the legacy response field, covered by a test), ledger concept NC-049. The schema census now flags any DATE/TIMESTAMP column named `data` by table.column; `events.data` is covered by an exception row tied to blocker BLK-C3-E6.
3. `payment_events.status` existed in the database and was written by raw SQL but was not mapped by the entity. Mapped (`processing | processed | failed`).
4. `apps/api/seed-operational.sql` and `apps/api/setup-supabase-complete.sql` inserted into columns that no longer exist (`nome_artistico`, `tipo`, `descricao`, `valor`, ...). Corrected to the canonical columns and values; the seed was executed against the migrated schema (exit 0). Operator messages in the SQL scripts translated to English.
5. Naming gate coverage gaps closed: new `dataFile` surface (SQL outside migrations, JSON, YAML, TOML) and new `toolMessage` surface (Portuguese prose in developer tooling strings), both ratcheted with ledger rows for the legitimate cases; 14 developer-facing messages translated in `apps/api/scripts`, `e2e` and the PT-column guard spec; 4 package descriptions and 1 active-document line translated.
6. Ledger corrections: NC-017, NC-019, CZ-015, CZ-016 were still `approved` with RENAME/MIGRATION required although the code and schema were already migrated (verified against the live catalog and the source); NC-041 described columns that were already renamed. Four undeclared product decisions are now blockers (BLK-TRANSACTIONS-V2-CUTOVER, BLK-SHARES-REGISTRY-CREATION, BLK-LEADS-INTERNAL-NOTES, BLK-EXTERNAL-SOURCE-SCAFFOLD).
7. `apps/api/migrate.mjs` applied the archived Drizzle snapshot (Portuguese columns, creates `events.data`) to Neon; first reduced to a refusing stub, then deleted with its siblings in the second order below.
